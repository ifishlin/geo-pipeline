# 動 `geo/prompts/` 之前，先讀這一份

這條路有七份 prompt（`facts`、`cast`、`spine`、`script`、`parts`、
`narrate`、`storyboard`），一千兩百行。**它們是這個專案最貴的地方** ——
改一行要五分鐘、一塊美金才知道結果，而且結果每次不一樣，所以「改了之後
好像有比較好」幾乎都是錯覺。

下面每一條都是在這條路上真的發生過的，附著量出來的數字。
完整的來龍去脈在 [geo/MISTAKES.md](../geo/MISTAKES.md)。

---

## 零、先問：這件事該不該用 prompt 解

**大部分想寫進 prompt 的東西，寫進去都沒用。** 動筆之前先過這一關。

### 兩種規則，成功率差很多

```
A 規範「寫出來的東西」   一句 30 字、結論落在誰身上、每句要標 role
                        模型一邊寫一邊就在遵守 —— 機率高

B 規範「要做的動作」     先打開圖看、先量再填、挑之前先排一張表
                        要離開寫字去做另一件事 —— 機率極低
```

**這條路違反過的規則全部是 B。** 送 prompt 對 A 有效，對 B 幾乎沒用。
B 只有兩條路：**變成流程的一步**（東西直接擺到它眼前），或**變成過不去
的門**。

### 想控制風格，加門是沒用的

門只會把答案退回去重擲。模型下一次的回答跟這一次無關，**退回重問不會讓
它變得比較懂你要什麼**，只會多花五分鐘。

想讓輸出長成某個樣子，去找**程式能直接控制的那一層**：版面的算式、
合成器的參數、資料結構裡有哪幾個欄位。

### 要模型複述一句話是機率，把那一句貼過去是必然

結尾卡要重述最後一句台詞，prompt 說了兩次，模型兩次都寫成**近似但不同**
的句子。改成程式直接抄那一行 —— 一次就對，永遠對。

同一個形狀：那道「檢查模型有沒有複述」的門在改成直接抄之後只會誤擋，
**擋的事情已經不可能發生，門就該消失**。

### 分工只有一條線

```
模型只講話    名字、詞、語義、哪一句配哪一塊地、這一段是什麼感覺
程式算數字    座標、縮放、秒數、字幕折行、什麼時候切鏡頭
```

模型填過一次 `count: 65000`，兩支畫法當場炸掉、三支花七到十秒安靜畫出
一團糊。**不是它的錯** —— 那張表寫著「多給 `count` → 數量畫成人」，
它就是六萬五千個人。**答應得到的事要做得到。**

## 一、範例會被當成答案

```
只輸出 JSON：{"keep": [1, 4, 7]}
```

這一行被模型**原封不動抄回來當答案**。

使用者 2026-09-27 直接交代：**「請你不要把範例寫進 prompt」**。

要說明格式就說欄位名和型別，不要給一份填好的。要舉例就舉**明顯不是答案**
的（用「⋯」、用占位符、用一句話描述），而且寧可不舉。

## 二、規則裡每一條退路都會被走到

prompt 給過一條「補不出就照抄原本那一句」的路。結果：**三句說明一字不差**，
抄的是事實清單上寫給挑事實的人看的備註。

退路不是保險，是**預設**。模型會走最省力的那條，而你寫的每一條退路都是
最省力的那條。

修法是把退路拿掉（留空），然後加一道門擋「兩句說明一模一樣」。

## 三、沒告訴它的規矩，不要罰它

這條在三小時內犯了兩次。

**第一次**：`spine` 排了 34 句被擋，而 prompt 只寫「大約 30 句，不用剛好」，
門在 27–33。它排 34 被退，**退回去的訊息才第一次讓它知道真正的界線**。

**第二次**：加了 `aside_gone_most`（不准連續超過 5 句沒有吐槽），門加完
第一次跑就叫了 —— 而我忘了把這條寫進 prompt。

```
門檢查什麼，prompt 就要印什麼。一條都不能少。
```

### 下限和上限是兩道門

`least_per_role`（至少幾句）擋得住「一句都沒有」，擋不住「寫太多」。
13 份 argue 的結尾**全部**連寫三句「回報」，而兩兩的字面相似度只有 0.07
—— 看不出字面重複，門就看不到。

prompt 那張表現在印「**剛好 2 句**」。只印下限，模型會貼著下限的反面寫。

同理，**只給上限，模型會貼著上限寫**，而貼著上限的每一張封面都是縮小的。
兩條線都要給（`{cover.aim_words}` 和 `{cover.most_words}`）。

### 數量和分布也是兩件事

`吐槽` 的門是「至少 2 句」。某一份排了 3 句，過 —— 而那三句落在第 4、
11、14 句，**第 15 到 26 句一句態度都沒有**，正好是觀眾最有感的那一段。

## 四、數字只留一份，prompt 從設定檔填

門檻在 `geo/data/rules.json`，外觀在 `geo/data/theme.json`，特效在
`geo/data/effects.json`。**prompt 裡寫 `{格子名}`，`ask.prompt_of()`
在送出前代入。**

```python
prompt_of("spine.md", rows=…, least=…, most=…)
```

那一支有兩道門：**少填一格就 raise**（不然那句話會變成「畫面要看到
`{see}`」，而模型會照那個字面去想 —— 它不會說「你少給我一個東西」），
多給的會出聲。

**手寫的數字會過期，指名的不會。** prompt 手寫過「十個字以內」，而十個字
要 1280px、畫面只有 932。

### 更進一步：那張表要從資料結構長出來

特效選單是 `effects.menu()` 從 `effects.json` 生的，卡片規格表是
`rules._card_table()` 從 `CARD_SHAPE` 生的。

手寫的話，加一種要改兩個地方，而**漏掉的那一邊不會報錯**。真的發生過：
`word`／`swap` 的畫法都會畫 `under`，而規格表和 prompt 都沒列 ——
九張卡從來沒有底下那行字。

**一個欄位列在哪裡，就決定了誰會用它。**

## 五、範圍寫太大的規則，跟錯的規則一樣糟

我寫過「`read` 裡不准補字，觀眾看不到」。而字幕當天就改成跟著唸了 ——
**看得到**。真正看不到的只有結尾卡標題。

規則從「整份不准補」縮成「**最後一句**不准補」。

寫得太大的規則會讓模型**照一個不存在的系統去推理**，而它推出來的每一個
結論都會是錯的，你還看不出來錯在哪。

## 六、簡化一份 prompt 的時候，要知道自己簡化掉的是哪一層

第一版的 `spine` 是一張日期表：

```json
{"when": "1953", "what": "丹麥修憲", "beat": "setup"}
```

十三個節點、三種 beat、兩道門。結果下一步最省力的寫法就是一行一個年份
—— **十五句旁白有十三句以年份開頭（87%）**，十一句的主詞是別人，
一句吐槽都沒有。

而**每一句單看都對**，所以沒有任何一道門攔得下來。攔不下來是因為沒有東西
可以攔：「好不好看」不是一個欄位。

根因是我把舊專案 417 行的 `spine.md` 簡化成 96 行，而**簡化掉的正好是
說故事的那一層**。修法：每一句標一個 `role`，十一種，門檢查那個宣告。
跑出來才會有「地球上最大的島，是一筆找零」這種句子。

## 七、不能檢查的怎麼辦：翻譯成一個必須宣告的結構

```
檢查不了   「要有起承轉合」「要好笑」「廢文要廢一半」
檢查得了   每句標 role、四種都要有、轉在前三分之一
           每句標 side（認真／廢），廢的那一半佔 40–62%
```

範圍從「整篇結構對不對」縮成「這一個轉夠不夠有力」。
**剩下那一點交給看片的人，而不是交給更多的散文。**

## 八、字數太少，寫出來是五言絕句

`PER_ROW`（一句話幾個字）本來是 21。使用者逐句指出九種破法：

```
問題沒問完        島也能用買的？那上面的人呢。
動作沒受詞        管它叫綠地，騙人來。          騙誰？來幹嘛？
人沒有身分        這島四千五百年前就有人。      觀眾以為在講外星人
代名詞沒先行詞    他們向挪威國王低頭            「他們」是誰？
壓縮出來的詞      它沒動，主人換了              沒搬家？沒反抗？沒同意？
文言腔            頭一次歸別人                  省字就會挑到最文的那個詞
專有名詞沒介紹    留下努克                      努克是什麼？
```

一句 20 個字塞得下「誰做了什麼」，塞不下「對誰做、為什麼、結果怎樣」。

改成 30。**而且不拿句數去換字數** —— 那等於少講故事。使用者：
「時間長短不是重點，故事講好才是」。

### 相關的一道暗門：多排一句，是從每一句的字數裡扣

骨幹的門本來是 `rows × 0.88 ~ 1.12`。26 句的片排到 28 句，過。

```
26 句 → 一句寫得下 16.8 字
28 句 → 15.2 字      ← 在範圍內，門不會叫
```

然後下一步要把 29 個字的 `point` 壓成 15.2 字，跑了四十分鐘寫不出來。
**超排的代價不是「片子變長」，是「每一句被壓扁」**，而那個代價門看不到。
範圍收到 ±6%，而且把「多排一句 → 每句少幾個字」算出來填進 prompt。

## 九、角色要「反應」，不是換個名牌講同一句

`parts` 那一步原本是**取代**：角色要講話就從旁白手上拿走一句。

量出來：11 句角色台詞跟被它取代的那句旁白，**字面相似度中位數 84%**，
八句只是把「它」換成「我」。

改成**追加**（`says` 那一列只會被插入、不會被指派）——
**做不到比擋得住可靠。**

後續量到的三件，每一件都是「沒寫進 prompt 所以沒發生」：

```
第一人稱      8 句只有 2 句有「我」      prompt 根本沒寫這一條
一個人包辦    格陵蘭講了 6/8 句          而它是受害的那一個，
                                        受害者複述自己被害不可能好笑
複述當反應    六句跟前一句相似度 23–42%  而「重申」這一類就是在授權它
```

最後一條是重點：**分類名稱本身就是授權**。`重申` 換成 `誇張`（不准用
旁白剛講過的數字，要用一句更大的話去頂），另外兩件變成門。

使用者的原話：「角色應該做的事是附和、吐槽、自嘲、用自己的語氣重申」，
以及「我等這句等到天荒地老」比「等這一句，等了一千年」好 ——
**有主詞，又好笑**。

## 十、要標記的東西，就地標在字裡面

停頓、語速、哪幾個字要換顏色 —— 這些**不要另開一欄讓程式回頭去找**。

```
就地      機場*沒有飛機*        ⏸0.3        ⟪-10 字⟫
另開一欄   {"emphasis": "沒有飛機"}
```

另開一欄會失敗三種：**找不到、找到兩次、跨行被切開**，而三種都不報錯。
就地標記的位置在字裡面，折到哪一行那個字帶著顏色走。

而且要強調的字**不一定在句尾**，所以也不能拆成前後兩截。

## 十一、問法決定失敗的方向

問「哪幾個是對的」要它產生長清單；問「哪幾個是錯的」清單短，
而且答錯時的預設是**留下**。

**選那個答錯了損失比較小的問法。**

## 十二、參考片的數字不是目標

我一度把參考片的每一個數字都訂成門檻：年份開頭 11%、提到主角 42%、
吐槽 3 句、對白 39%、六群。

使用者說了三次「那片只是參考」。他是對的 —— **那樣做出來的每一支都會是
它的複製品**，而那些數字只是一個樣本，不是規律。

```
原則留著    旁白要有態度、故事要有主角、一句要接得上上一句
數字降級    只擋明顯壞掉的。年份開頭 87% 是壞掉，40% 不是
```

**要長什麼樣是人的選擇，門只負責擋掉不像故事的東西。**

順帶一提，抄錯參考片也發生過：`storyboard.md` 裡寫著「參考頻道 72 秒切了
130 次」，那是**硬切風格的紐約那支**，而我們要做的是從頭滑到尾的格陵蘭
那支。結果 125 格擠在 122 秒裡，**一格短於 0.9 秒就滑不動**，63 個接縫
只能硬切。我花時間調「什麼時候該滑」的門檻，而根本不是門檻的問題。

**一個參數調不動的時候，先確認要調的是不是它。**

## 十三、改了 prompt，快取要跟著過期

`raw_stale()` 原本只比「上游的**資料**有沒有比這個答案新」。

我在 `script.md` 加了一條規則然後跑 —— 答案是照舊規則寫的，被新的門擋下來，
**重跑幾次都一樣**，因為問題在快取裡，而快取說自己沒過期。

**一個快取的有效條件，要包含所有會改變答案的東西。** 少算一項，那一項
改了就會安靜地沿用舊的。現在 `raw_stale()` 也比 prompt 檔的時間。

## 十四、重問一趟五分鐘，所以退回去要有節制

```
填錯       不認得的種類、地圖上沒有的地名、清單外的值   → 停（SystemExit）
少填       26 個動作裡有一個缺欄位                     → 丟掉那一個，出聲
有預設     清單的第一個就是預設                        → 直接用，不要退回
```

26 個動作裡少一個欄位而重問一趟是五分鐘、$0.8 —— **那個代價不成比例**。
丟掉並出聲，人看得到「少了什麼」就好。超過三分之一被丟掉才停。

同理，**有合理預設的東西不該列成必填**，那會讓模型為了一個程式填得出來
的空格被退回。

## 十五、兩個地方做同一件事，就會有一個是假的

一道門要求模型填一個它看不到的東西（連續卡片的底），而那件事後來搬給
程式做了。門還在要求、prompt 還在教，而程式已經在做 —— 我寫的「模型填了
就用它的」讓**真正看得到畫面的那一支永遠不會被叫到**。

**搬走一件事，要把原本那個地方的要求一起拿掉。**

## 動 prompt 的檢查清單

```
1  這件事是 A 還是 B？B 的話先想流程和門，不要寫進 prompt
2  有沒有給出一個填好的範例？拿掉
3  有沒有給退路？拿掉，留空
4  門檢查的每一條，prompt 都印了嗎？上限和下限都印了嗎？
5  數字是手寫的還是 {格子} 代入的？表是手寫的還是從資料結構長出來的？
6  規則的範圍是不是寫得比實際大？
7  改完之後，快取會不會沿用舊答案？
8  跑完要看的不是「有沒有比較好」，是量出來的數字 —— 而且要有對照組
```

最後一條最重要：**一趟只改一個變數**。這條路上「調了三件事然後變好了」
的紀錄，事後沒有一次分得出是哪一件。
