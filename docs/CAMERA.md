# 鏡頭

**這一份最重要的一句話寫在最前面：討論鏡頭，一律畫圖。**

「格陵蘭在畫面偏左上」「丹麥被字幕擋住」—— 這種話聽起來合理，而且經常是
錯的。一個晚上投影連錯四次，四次都不會報錯，四次都是**看圖才發現的**：

```
merc_y 的方向搞反
view() 回傳的順序記錯
TILE_SIZE 猜成 256（其實是 512）  → 得出「49% 的鏡頭被偷偷推近了」的假結論
說丹麥被字幕擋住                  → 使用者：「丹麥不在那個位置」
```

最後那個的根因是**取樣點取錯**：在鏡頭的 85% 處截圖，而 `when: late` 的
鏡頭正好把移動放在後段。截圖要截**那一格開始的時候**。

怎麼畫：`geo/pipe/shot.py`。它截一格、用 `camera.view()` 把經緯度換算成
畫面座標，畫上每一塊地的外框、合併後的框、畫面正中央的十字、字幕帶。
**不要自己另外寫一份投影** —— `Map_Animation/src/engine/projection.ts`
是真相，`shot.py` 是逐行照抄的。

---

## 模型不給座標

**模型只講話，程式算數字。** 分鏡那一步模型說的是「這一格要看到哪幾塊地」
和「推近這塊地的西北」，座標、縮放、什麼時候動，全部是程式算的。

```python
camera.merge([bbox, bbox, …])     幾塊地的外框併成一個
camera.fit(bbox, pad=, hold=, lift=)   讓那個外框剛好進畫面的相機
camera.view(shot)                 反過來：從相機算回看得到的範圍
camera.part_of(bbox, "西北")       九宮格的一格 —— 「西北角」算得出來
```

`fit()` 的 `hold` 和 `lift` 是同一件事的兩半：先用比較矮的框算縮放
（字幕在下面，`hold=0.72` 就是把字幕那塊讓開），再把中心抬上去。
**兩個分開是因為它們可以不相等** —— 留 28% 給字幕不代表主體要正好抬 14%。

`part_of()` 切的是 **0.45**，不是剛好三等分。格子重疊一點，推近之後才不會
剛好切在邊界上、把要看的東西切成兩半。而且緯度那一軸用**麥卡托**算，
不是直接對緯度取中點 —— 高緯度直接切的話，北邊那一格會比南邊矮一截。

## 幾個量出來的常數

```
WORLD = 512.0     MapLibre 的圖磚寬度。**不是 256**，猜錯過一次，
                  而猜錯的結論是「一半的鏡頭被偷偷推近了」（假的）
floor_zoom(1920)  ≈ 1.907　再縮下去 MapLibre 會把中心釘在赤道
TINY = 120.0      小於這麼多像素的一塊地，只靠填色看不出來
PART = 0.45       九宮格每一格佔外框的比例
```

`TINY` 是量出來的：「格陵蘭＋丹麥」那一格算出 zoom 2.714，**相機算得完全
正確**（外框確實裝得下），而丹麥在畫面上只有 66×27 像素，紅色一小點貼在
右邊 —— 鏡頭完全沒有用。`covers()` 抓不到這種，因為它問的是「在不在畫面
裡」。低於 `TINY` 的那一塊要改用圈或標記去指，不能只靠填色。

**直向 9:16 的畫面最多裝得下約 202° 經度** —— 北約（186°）勉強進得去，
再多就得退而求其次：挑裝得下的最大幾個成員，並出聲。

## 鏡頭是滑的，不是切的

參考頻道是從頭滑到尾。抄錯過一次：`storyboard.md` 裡寫著「參考頻道 72 秒
切了 130 次，平均 0.55 秒一次」—— 那是**硬切風格的紐約那支**。

結果 125 格擠在 122 秒裡，平均 0.85 秒一格，而**一格短於 0.9 秒就滑不動**，
63 個接縫只能硬切。我花時間調「什麼時候該滑」的門檻，**而根本不是門檻的
問題，是切點太多、沒有時間滑**。

改成「一格兩秒半」（`AIM_SECONDS = 2.5`）之後，同一組門檻算出來是切 20、
滑 27。

**一個參數調不動的時候，先確認要調的是不是它。**

## 減少不必要的切換（使用者 2026-09-27 交代）

> 「鏡頭切換的次數要減少，頭都暈了。例如丹麥跟格陵蘭來回講話，就不要
> 鏡頭一下丹麥一下格陵蘭。找一個畫面可以看到兩者。」

兩個角色對話**共用一個取景**，不要來回切。真的要給特寫，用特效：

```
一個對象      「推近」（closeup）—— 改的是相機，在 storyboard 那一步做
多個對象      「上台」（lift_to_stage）—— 剪影拉到畫面前並排，
              地圖壓暗。四個以內；再多就用「亮燈」在全球地圖上點
```

門：`SWAP_MOST = 2`，只數**真正的來回**（前一格和後一格看的是同一組、
而中間這一格跟它們沒有交集）。推近的角落折進判斷的鍵裡，
所以「推近西北 → 推近東南 → 推近西北」也算。

## 一格停多久

```
AIM_SECONDS = 2.5    目標
STARE       = 6.0    超過就出聲
STARE_MOST  = 9.0    超過就擋
FEWEST      = 8      至少幾格
```

`STARE` 只出聲不擋的那一版，放過了一格停十一秒的片。**只出聲的門要有人
看才算存在。**

## `camera.when` 和 `camera.travel`

```
when     late / early / whole   —— 這一格的移動放在前段、後段、還是整格
travel   0.5 → 鏡頭真的在動 29%
         0.75 → 45%
         whole → 74%
```

目前整支片鏡頭在動的比例只有 **20%**，而目標是「運鏡絲滑」。
這兩個值還沒定案（`geo/TODO.md`）。

順帶一個對照：參考頻道是 **60fps**，我們是 30fps —— 同樣的移動速度，
他們看起來會滑得多。

## 報告要問同一支函式

`_legs()` 回分段清單，而報告本來是**數段數**來判種類（1 段＝切、2 段＝滑）。
後來「滑」從兩段改成三段，報告就開始說「滑 0、拉遠 27」。

**成品是對的，報告是錯的** —— 而報告是唯一有人會看的那一面。它說錯了，
等於這件事從來沒被檢查過，還讓一個做對的東西看起來壞掉。

改成 `_legs()` 自己回種類，不讓別人從形狀推。
