# 這支片的分鏡

一支**地圖短影音**。畫面只有一張地圖：鏡頭在上面滑動、把某幾塊地塗上顏色。
沒有照片、沒有實拍、沒有卡片。

你決定**每一段要看到哪裡**，以及**哪幾個接縫是真的斷點**。

---

## 最重要的一條：鏡頭是滑的，不是切的

觀眾看的是一張地圖。地圖一直跳，人會暈，而且會失去「這些地方彼此在哪」
的感覺 —— 而那正是地理短影音唯一能給的東西。

```
預設   鏡頭從上一個地方滑到下一個地方。觀眾看得見自己怎麼過去的
例外   硬切。只在真的斷掉的地方用
```

什麼叫真的斷掉：

```
換時代      「1946 年」→「然後是 2025 年」
抖包袱      前一句鋪、這一句翻
跳到無關的地方   兩個地方隔著半個地球，而這句話沒有在講「從這裡到那裡」
```

**其他一律用滑的。** 你不用寫怎麼滑、滑多久 —— 那是程式算的。你只要在
真的該斷的地方標 `cut`。

---

## 第二條：一格要夠久

鏡頭要滑得動，就得有時間。一格**兩到三秒**是舒服的；一秒以下的格子
滑不動，只能硬切，而連續幾個那種就是在閃。

這支片 {seconds} 秒。**大約 {aim} 格**是對的 —— 不是 {count} 格
（那是一句一格），更不是一百格。

一句話裡面可以完全不換畫面。**一段話共用一個地方，是正常的。**

### 不要來回切

**最該避免的是 A → B → A。** 觀眾剛認得畫面上是哪裡，它又換回去了 ——
頭會暈，而且什麼都沒記住。

```
✗  甲＋乙 → 丙 → 甲＋乙 → 丙
✓  甲＋乙＋丙（一個畫面裝下三邊，整段不動）
```

**兩個角色來回講話的時候尤其不要切。** 一邊說一句、另一邊回一句、再換
回來 —— 那是一段對話，不是三個場景。找一個**兩邊都看得到**的取景，整段
停在那裡，讓聲音去分誰在講。

真的需要特寫某一個的時候再切，而且**切過去就待著**，不要切回來又切過去。

程式會數：一整支片裡 A→B→A 這種來回**最多 {swap_most} 次**。

### 但是不能停超過 {stare_most} 秒

盯著同一塊地十秒不動，觀眾會以為片子卡住了。

最容易犯的地方是**那幾句台詞沒提到新的地名**——講的都是主角，所以
畫面就一直停在主角身上。這種時候還是要換，只是換的是**看法**不是地方：

```
推近    從整座島推到它南邊那一角（講那裡發生的事）
拉遠    退開，讓它跟旁邊的國家一起入鏡（講它在世界的哪裡）
換對象  主角配上這句話提到的另一個角色
```

`see` 換一組地方，鏡頭就會動。**沒有新地名也可以換畫面。**

---

## 第三條：畫面要在故事講的位置

這一段在講哪裡，畫面上就要看得到哪裡。聽起來理所當然，但很容易破功 ——
台詞已經換了地方，而鏡頭還停在上一個，觀眾就得自己想像。

程式會檢查：**一句台詞裡提到的地名，必須在那一格看得到**。
對不上會被退回。

---

## 你只給名字和詞，不要給數字

```
要給      地方的名字（從底下那張清單挑）、句子裡的某個詞
不要給    經緯度、縮放級數、秒數、像素
```

你看不到地圖，算不準；而外框查得到，算得準。給了座標會被丟掉。

## 可以加的動作

除了鏡頭和塗色，一格還可以加動作。**只能從這張表挑，不要自己想一個。**

{moves}

### 挑的原則

**動作是把台詞講的事照實演出來，不是裝飾。** 那一句說「從這裡開船到那裡」，
就畫一條兩地之間的線；說「它很無奈」，就給它一張無奈的臉。

```
✅  台詞｜（一句在講「人從甲地遷到乙地」的話）
    航線　從：甲　到：乙　　　　真的有人從那邊過來

✅  台詞｜換主人這種事，它每次都是最後一個知道。
    表情　誰：主角　無奈　　　　　那一句就是在講它的感受

❌  台詞｜（一句單純交代制度改變的話）
    閃一下　　　　　　　　　　　　這句話沒有翻面，閃光只是裝飾
```

**好笑不歸你管** —— 台詞已經負責了。你只要把它說的事演出來。

### 不要每一格都加

大部分的格子**什麼動作都不要**，鏡頭移動加塗色就夠了。

```
一支片大概    表情 3–6 次、航線 1–3 次、圈起來 0–2 次、
              依序亮 0–2 次、閃一下最多 2 次
沒有動作的格   佔一半以上是正常的
```

加太多的話畫面會一直有東西在跳，觀眾累。**寧可少加。**

---

## 每一格的欄位

```
line     這一格從第幾句開始（下面的編號）
word     在那一句的哪個詞上切進來。空字串＝那句話一開頭
see      要看到哪些地方。相機由它算出來
tint     要塗色的地方。不寫＝跟 see 一樣
mark     要標記哪些點（會畫一個標記和名字）。可以是空的
cut      true ＝ 這裡硬切。不寫或 false ＝ 鏡頭滑過來
why      這一格為什麼存在 —— 一句話
do       這一格要加的動作，可以是空的（大部分是空的）
```

`word` 要**一字不差**地出現在那一句裡，而且在那句話裡只出現一次。

`see` 放兩個地方，相機會退到兩個都看得見 —— 講「這兩邊的關係」的時候
用它。但**大小差很多的兩個放一起，小的那個會變成一個點**，那種情況下
小的那個改用 `mark`，或者用「面對面」那個動作把兩邊拎起來各自放大。

## 怎麼回答

只回 JSON，不要解釋：

```
{"shots": [
  {"line": 0, "word": "", "see": ["甲"], "cut": true, "why": "開場先立在這裡"},
  {"line": 4, "word": "（那一句裡的某個詞）", "see": ["乙", "甲"], "why": "…",
   "do": [{"move": "航線", "從": "乙", "到": "甲", "why": "…"}]},
  {"line": 7, "word": "", "see": ["甲"], "why": "…",
   "do": [{"move": "表情", "誰": "甲", "mood": "無奈", "why": "…"}]},
  …
]}
```

`do` 裡每一筆要有 `move`（動作的名字）、那個動作要的角色、和 `why`。
**寫不出 `why` 就不要加** —— 加不出理由的動作就是裝飾。

照時間順序。**第一格一定是 `line: 0`、`word: ""`。**

寫完自己數一次：幾格？如果超過 {most} 格，那就是切太碎了，
回去合併 —— 一段話共用一個地方是正常的。
