# 建這條路的時候抓到的錯

全部是 2026-09-26 一個晚上抓到的。**每一個都跑得完、exit code 0、
每一道當時存在的門都過** —— 它們只在有人打開畫面或量一次的時候才存在。

---

## 一、相機算得完全正確，鏡頭完全沒用

一個點單獨當鏡頭的時候，我給的外框是「剛好裝得下那個點」（±0.4°／±0.25°），
算出來 zoom 9.6。

```
紐約那一格      變成街道圖，看不出是紐約
圖勒基地那一格   一整片白色的冰，連海岸線都沒有
```

`covers()` 說裝得下 —— 它問的是「在不在畫面裡」，而那個問題的答案是對的。

**點是用來「指」的，不是用來「看」的。** 改成 ±7°／±3.5°（`AROUND`），
算出來 zoom 4.7：紐約看得到整個東岸，圖勒看得到格陵蘭西北角和海。

---

## 二、外框取全部領土，鏡頭就對著大西洋中間

```
挪威     −9.1 → 33.6    含央棉島
法國     −62 → 56       含法屬圭亞那、留尼旺
歐洲共同體 緯度 −21 → 60   含加那利、亞速
```

拿那個外框算相機，該亮的那塊地變成一個點。改成取**主體**：Natural Earth
每一筆都有 `LABEL_X/Y`（人挑過的、該放國名的地方），取包含那個點的那一塊。

然後丹麥只剩日德蘭半島，**哥本哈根在 12.6 被切在畫面外**。所以主體要能長：
把 `NEAR` 度以內的島併進來。

而 `NEAR = 4.0` 的時候挪威變成 58–80，因為**熊島（北緯 74.4）當了跳板** ——
它離本土 3.2 度所以併進來，併完北界推到 74.5，斯瓦巴就只差 1.6 度了。
一塊一塊接力，這是逐輪長大必然的行為。

掃 4.0 / 3.0 / 2.5 三個值，3.0 修好挪威而其他不動，2.5 跟 3.0 完全一樣 ——
**3.0 在穩定帶中間，不是踩在懸崖邊上。**

## 三、「91 個切點、平均 1.28 秒一格」，而畫面二十秒沒動

模型回了 91 個切點，其中一長串的相機、塗色、標記完全相同。畫面上那是一格，
不是十格。而報告說「平均 1.28 秒一格」，聽起來節奏很快。

**數字要說真話。** 併掉相同的（`_same()`），再另外印一個「不同的畫面幾種」。
第一版十二張取樣裡有八張一模一樣，而當時沒有任何數字說得出這件事。

現在有 `FEWEST` 那道門：整支片少於 8 種畫面就 raise。參考頻道 72 秒用了 14 種。

---

## 四、字幕把日期腰斬

「2026 年 9 月 22 日」被 12 字上限切成「2026 年 9 月 2」和「2 日」。

中文一個字一個字切看起來沒問題，**正是因為中文本來就一個字一個意思**；
數字和外文字不是。改成先切成「原子」（數字含單位是一個原子），再照原子排。

然後出現孤兒：「1991 年才被報紙挖出」＋「來。」，兩個字閃一下。修法是
先算塊數再照平均長度排，再加一道「太短就併進鄰居、併不下就借字」。

那一道自己也錯過兩次：**借完字之後前一塊變短了，而掃描已經走過開頭那個
孤兒**（第一版只在「併」之後重掃）；改成重掃之後又寫了 `at == 0: return`，
把後面的孤兒一起放掉。現在是「救不了的記下來，繼續救別的」。

## 五、量響度的門，量錯地方

`ffmpeg -v error … ebur128` 永遠回 `None`，於是門一直叫「loudnorm 可能沒
生效」—— 而它生效得好好的，**−14.6 LUFS 正中目標**。

`-v error` 會把摘要一起吃掉：ebur128 的「Integrated loudness」印在 info 等級。

**判錯的檢查比沒有檢查糟 —— 它會叫人去修沒有壞的東西。**

## 六、防「沒填的格子」的門，被維基的原文誤觸

`prompt_of()` 掃填完的全文找 `{xxx}`，而塞進去的維基原文裡本來就有
`{parabr}` 這種字。門當場叫「facts.md 還有沒填的格子：parabr」。

**要掃樣板，不是掃填完的結果。** 同一個形狀：這道門自己犯了它要擋的錯。

## 七、Azure 連不上，而錯誤訊息說的是網路

```
Connection failed (no connection to the remote host)
wss://germanywestcentral"/
```

設定檔那一行是 `region = "germanywestcentral"   # 金鑰綁區域…`，而我照
`split("=")` 取等號後面的**全部**，把註解一起送出去了。

錯誤訊息長得像網路問題。**送出去的東西要抓引號裡那一段。**

## 八、音色回成功、書籤全回來、每一格都對，而兩個角色是同一個人

第一版四個角色只指定音色。量完基頻：

```
旁白  198 Hz      ← zh-TW-HsiaoChenNeural
丹麥  202 Hz      ← zh-TW-HsiaoYuNeural
```

兩個都是 zh-TW 女聲，同一個音域，在耳朵裡是同一個人。而 Azure 回成功、
36 個書籤全回來、報告每一格都對。

現在 `spread_ok()` 每次合成完逐段量一次，兩兩差不到 1.15 倍就 raise。
**能算出來的就不要靠耳朵記得去聽。**

## 九、上游重寫了，下游的檔案還在

改了台詞重跑配音，而 storyboard、scene、成片全都還在 —— 每個檔案都存在、
每道門都過、`make` 看到「跑過了」就跳過，於是成片裡是**舊的畫面配新的聲音**。

更隱蔽的是模型那份 `*.raw.json`：storyboard 的答案是照句子編號寫的
（「第 12 句切到格陵蘭」），台詞一改，那些編號指的就是別的句子，
而程式照樣算得出秒數、照樣壓得出片。

兩個都用時間比：`paths.stale()` 和 `paths.raw_stale()`。時間比較笨
（碰一下檔案就算改過），但**誤判的代價是多跑一次，漏判的代價是一支錯的片**。

## 擋不住的

**一、地名靠掃字串認。** 稿子寫「聯合國大會場邊」掃不到紐約。故事檔的
`places` 可以補，補的會標 `+` ——但沒補、而且沒人發現的那一次，畫面只是
停在上一格。

**二、`quote` 對得上原文，不代表事實是對的。** 那道門問的是「這句話有沒有
出處」，不是「這個出處說得對不對」。維基寫錯的話，整條路都會照著錯。

**三、`entity` 少寫一個地方，那個地方就不可能出現在畫面上**，而畫面照樣
完整 —— 它只是少了一格。這是「靜靜回報零」在這條路上的樣子。

**四、我沒有真的看完那支片。** 我抽了十二格看，而它有 3502 格。
`verifyCuts.ts`（隔壁寫的）可以逐格比對，還沒接上。

## 十、門擋下來了，而半成品已經躺在那裡

配音那一步中間有兩道門（書籤數、音色分得開），而**合成在門之前**。
音色那道門擋下來的時候，新的 `said.wav` 已經寫進 `4-voice/` 了，
而 `said.json` 還是上一版的。

下一次跑：

```
done()   看到目錄裡有東西 → 「跑過了」
stale()  看到 wav 比 script 新 → 「沒過期」
make     跳過這一步
```

於是**成片用的是上一版台詞的聲音，而每一個檔案都在、每一道門都過**。
我是看到 storyboard 印出「133.1 秒、49 句」才發現的 —— 那是三個步驟之前
的數字，而新的台詞是 42 句。

修法跟 `paths.save()` 一樣：**寫進 `4-voice.part/`，全部做完、每道門都過，
才整個 rename 上去**。半路失敗就什麼都沒有，而「什麼都沒有」是 `done()`
判得出來的。

「破壞已經發生，產出還沒發生」，這個專案記過的第五次。

## 十一、一格裝不下，整趟三分鐘白費

模型挑了「美國＋挪威」，橫跨 156 度，算出來要 zoom 1.89 而畫面的地板是
1.91 —— **差 0.02**。`camera.fit()` 直接 raise，於是前面三分鐘的模型呼叫
和一分鐘的配音全部作廢。

而那一格是**救得回來的**：少留一點白邊就裝得下。

改成讓步三次（照設定 → 邊留少一點 → 連字幕那塊空間都拿來裝），每一次讓步
都出聲。真的裝不下才停，而且訊息說得出是第幾句、哪幾個地方、該怎麼拆。

**門要擋的是「不對」，不是「不方便」。**

## 十二、叫模型模仿錯的參考片

`storyboard.md` 裡寫著「參考頻道 72 秒切了 130 次，平均 0.55 秒一次」。

那是**紐約那支**，它是硬切風格 —— 一句話裡切三四次，從頭跳到尾。
而這條路要做的是格陵蘭那支，它從頭到尾在滑（那份拆解的第一段就寫著
「衛星圖由歐洲快速推到丹麥」）。

結果：125 格擠在 122 秒裡，平均 0.85 秒一格，而**一格短於 0.9 秒就滑不動**
—— 63 個接縫只能硬切。

我花了時間在調「什麼時候該滑」的門檻，而根本不是門檻的問題，
**是切點太多、沒有時間滑**。改成「一格兩秒半」之後，同一組門檻算出來是
切 20、滑 27。

**一個參數調不動的時候，先確認要調的是不是它。**

## 十三、報告說「滑 0」，而 27 個全是滑的

`_legs()` 回的是分段清單，而報告數段數來判種類：1 段＝切、2 段＝滑、
3 段＝拉遠。後來「滑」從兩段改成三段（停、走、到位停），報告就開始說
「滑 0、拉遠 27」。

成品是對的，報告是錯的。而**報告是唯一有人會看的那一面** —— 它說錯了，
等於這件事從來沒被檢查過，還讓一個做對的東西看起來壞掉。

改成 `_legs()` 自己回種類，不讓別人從形狀推。同一個形狀這個專案記過
（英文版壓完回報「用中文音色唸」）。

## 十四、分段之後總長多了 0.46 秒

一格拆成三段（停、走、到位停），而我的補救分支寫成「room 至少 0.3 秒」——
於是短格子的三段加起來比那一格長。105 段累積下來，畫面 122.6 秒、
聲音 122.14 秒。

那是**壓完十分鐘之後**在「影音等長」那道門才叫的。現在 `scene` 這一步
自己對一次：畫面加起來要等於聲音，差超過 0.05 秒就停。

便宜的檢查要放在貴的步驟前面。

## 十五、會亂叫的警告等於沒有警告

「一句話裡不要放兩個數字」這條，第一版直接數 `\d+`：

```
2026 年 9 月 22 日     被數成 3 個
1261 年…1814 年        被數成 2 個（那是刻意的壓縮）
70.8%                  被數成 2 個（小數點拆開）
```

五句裡有五句被標記，而其中四句沒有問題。**一個每次都叫的警告，下一次
就沒有人看了。**

修法是先把日期收成一個、小數點接回去。而中文數字（「八個盟國」）我
決定不抓 —— 要抓就得分辨「三個主人」和「八個盟國」，那條界線我畫不出來。
**寧可漏也不要亂叫**，而這個限制寫在函式的說明裡。

## 十六、我的檢查看秒數，渲染器按幀算，兩邊都「對」

加了「分段後總長要等於聲音」那道門，它說 122.138 對 122.137，過。
壓完十分鐘之後，影音那道門說**影片 122.58、聲音 122.14，差 0.45 秒**。

原因：`settle` 是 0.25 秒，在 30fps 剛好是 **7.5 幀** —— 每一次都往同一邊
進位，而 27 個滑鏡頭累積出 13.5 幀。

```
我這邊    每一段的秒數相加 = 122.138   ✅
渲染器    每一段各自 round(秒×30) 再相加 = 3677 幀 = 122.58   ✅
```

**兩個都算對了，而成片是壞的。** 這種錯只有在「把兩邊放在一起比」的時候
才看得見，而我的門只看了自己那一邊。

修法是我這邊就對齊到整幀，而且**從絕對時間算，不是每一段各自取整**：
每個邊界各自 `round(t × fps)`，相鄰兩個相減就是那一段的幀數 —— 誤差不累積。
（隔壁的 `Timeline.scenes()` 早就是這樣寫的，註解也寫著理由，我沒看。）

**一個剛好落在 .5 的常數，會把「隨機的捨入誤差」變成「每次同方向的偏移」。**

## 十七、兩個標籤疊成「丹麥根」

丹麥（9.02, 55.97）和哥本哈根（12.57, 55.68）在 zoom 3 的畫面上只差
47 像素。兩張白底名牌直接互相蓋掉，畫出來是「丹麥根」。

48 個標籤有這個問題，橫跨整支片。而它**畫得出來、不會報錯、每一道門都過**
—— 我是把十二格排成接觸表、放大看才發現的。

修法是投影到畫面上算距離，靠太近的往上疊開（`_unstack()`）。往上不往下：
名牌底下就是它指的那個點，往下會蓋住標記本身。

**這一項到現在還沒有門。** `_unstack()` 是修法，不是檢查 —— 它疊開之後
有沒有疊對，仍然只有人看得出來。真正的門要逐格比像素（隔壁的
`verifyCuts.ts` 是那個形狀），還沒接上。

## 十八、骨幹是日期表，所以台詞是年表

使用者看完成片：「把插話拿掉，剩下的台詞本身就不好笑。」

量出來：**十五句旁白有十三句以年份開頭**（87%），十一句的主詞是別人
（丹麥修憲、挪威被劃走、美國人不支持動武），一句吐槽都沒有。那是一份
清單，順序換掉也不會壞。

根因在上一步。第一版的 spine 是：

```
{"when": "1953", "what": "丹麥修憲", "beat": "setup"}
```

十三個節點、三種 beat、兩道門。**那是一張日期表**，所以下一步最省力的
寫法就是一行一個年份 —— 而每一句單看都對，所以沒有任何一道門攔得下來。
攔不下來是因為**沒有東西可以攔**：「好不好看」不是一個欄位。

舊專案的 `assets/prompts/spine.md` 是 417 行、單位是「一句」、每句宣告
它在論證裡幹嘛（吸引／建立／打破／解釋／回報）、六道門。我開這條路的時候
把它簡化成 96 行，而**簡化掉的正好是說故事的那一層**。

修法：每一句標一個 role，十一種，門檢查那個宣告。跑出來的骨幹有
「地球上最大的島，是一筆找零」這種句子 —— 第一版完全生不出來。

**簡化一份 prompt 的時候，要知道自己簡化掉的是哪一層。**

## 十九、把參考片的比例當成目標

我一度把那支參考片的每一個數字都訂成門檻：年份開頭 11%、提到主角 42%、
吐槽 3 句、對白 39%、六群。

使用者說了三次「那片只是參考」。他是對的 —— **那樣做出來的每一支都會是
它的複製品**，而那些數字只是一個樣本，不是規律。

改成：原則留著（旁白要有態度、故事要有主角、一句要接得上上一句），
數字降級成「擋明顯壞掉的」。年份開頭 87% 是壞掉，40% 不是；一句吐槽都
沒有是壞掉，五句還是三句不歸門管。

**要長什麼樣是人的選擇，門只負責擋掉不像故事的東西。**

## 二十、查「格陵蘭」查到 0/43，而每一句的主詞都是它

「主角要一直在」那道門查的是字面上有沒有「格陵蘭」三個字。量出 0/43，
擋下來了。

而那份稿子是這樣寫的：

```
它什麼都沒做，主人就換了。
它不是被發現的，人住了四千年。
島沒有賣。要進來的人，得它點頭。
```

主角一直在，用的是「它」和「島」—— **一句一個全名才是壞的中文**。
我的門在罰它寫得好。

改成認代名詞（故事檔的 `hero_as`），而且加一道「最長連續幾句沒有主角」
—— 比例是弱的代理，真正要擋的是「主角整段消失」那一段連續的沉默。

即便如此還有極限：中文會省略主詞（「走要付得起」的主詞就是它），
字面查不到。這個限制寫在函式的說明裡。

## 二十一、同一個數字兩個地方各算一次（第 N 次）

```
spine.py    rows = aim / 2.8        ← 隨手寫的常數，排出 43 句
script.py   budget() 用正式算式       ← 每句 1.06 秒那條，給 505 字
```

43 句在 505 字的額度下放不下：寫出來 129 秒，目標 116。

而且順帶發現**一句 12 個字太短** —— 中文寫不下「格陵蘭」（三個字）加上
內容，所以模型把主角擠掉。改成 15 字、37 句。

`rows_for()` 一支，兩邊問它；`budget()` 再吃骨幹**實際排的**句數，
不是理想的那個。

## 二十二、跑了 21 分鐘，回報「模型沒有回答」

真正的訊息是：

```
API Error: Claude's response exceeded the 32000 output token maximum
```

那一行就在 stdout 裡，而我的程式看到 `exit != 0` 就印「模型沒有回答
（exit 1）」，把它丟掉了。**又一次是報告錯了** —— 檔案裡有答案，
畫面上沒有。

兩件事一起修：錯誤訊息照抄出來，以及把上限調到 64000（模型在交出 JSON
之前會想很久，那些也算在輸出裡）。

## 二十三、改了 prompt，快取的答案照樣被沿用

`raw_stale()` 比的是「上游的**資料**有沒有比這個答案新」。

我在 `script.md` 加了一條「不要出現拉丁字母」，然後跑 —— 答案是照舊規則
寫的（裡面有 `Hans Egede`），被那道新的門擋下來。**重跑幾次都一樣**，
因為問題在快取裡，而快取說自己沒過期。

「規則改了、答案沒跟著改」跟「資料改了、答案沒跟著改」是同一件事，而我
只處理了後者。現在 `raw_stale()` 也比 prompt 檔的時間。

**一個快取的有效條件，要包含所有會改變答案的東西。** 少算一項，那一項
改了就會安靜地沿用舊的。

## 二十四、門和它印的範圍各算一次，照它說的改是改不過的

`spine` 排了 34 句被擋，訊息說「容許 26–34」—— 而 34 正是被擋掉的那個數。

比的是 `rows * 1.12`（33.6），印的是 `round(rows * 1.12)`（34）。
同一個界線兩個地方各算一次，就會有一個是錯的，而錯的那個是**給人看的
那一面**。照那句話去改，改幾次都過不了。

算一次（`math.ceil` / `math.floor`），門和訊息用同一份。

而且順手發現第二件：那個範圍**從來沒告訴過模型**。prompt 只寫「大約 30
句，不用剛好」，門在 27–33。它排 34 被退，退回去的訊息才第一次讓它知道
真正的界線 —— **那是在罰它不知道的規矩**。範圍現在填進 prompt。

## 二十五、逾時之後什麼都沒留下，四十分鐘全黑

`subprocess.run(timeout=)` 一砍，回答還在 pipe 裡就沒了。一趟 40 分鐘的
呼叫結束時，我手上只有一行 `TimeoutExpired`。

而那時候最需要回答的問題是：**它是在慢慢寫，還是從第一秒就卡死？**
這兩件事要救的方向完全相反（題目太難 vs 環境壞掉），而零產出讓它們
長得一模一樣。

改成 `Popen` ＋ 邊讀邊寫檔（`os.read`，有一個 byte 收一個 —— 用
`pipe.read(n)` 會等湊滿 n 個字才回來，那等於沒改），每 60 秒印一次
收到幾個字，砍掉的時候把已經收到的留在檔案裡並印出最後 120 字。

**順便量到一件事**：`--output-format text` 是整份寫完才一次吐出來的，
所以心跳一路顯示「收到 0 字」，最後一秒才跳到 1648。要看到真正的過程
得換 `stream-json`。**加了儀器才知道儀器量不到** —— 但至少現在知道了。

## 二十六、門看得到句數，看不到每一句被壓得多扁

骨幹的門是 `rows * 0.88 ~ 1.12`。26 句的片排到 28 句，過。

而秒數是固定的，所以多出來的那兩句是從**每一句的字數**裡扣的：

```
26 句 → 一句寫得下 16.8 字
28 句 → 15.2 字      ← 在範圍內，門不會叫
```

然後寫台詞那一步要把 29 個字的 `point` 壓成 15.2 字的台詞，跑了四十分鐘
寫不出來。**超排的代價不是「片子變長」，是「每一句被壓扁」**，而那個
代價門看不到。

範圍收到 ±6%，而且把「多排一句 → 每句少幾個字」算出來填進 prompt。

## 二十七、下限擋得住「一句都沒有」，擋不住「全擠在前半段」

`吐槽` 的門是「至少 2 句」。某一份排了 3 句，過。

而那三句落在第 4、11、14 句 —— **第 15 到 26 句，也就是川普開價、關稅、
簽約那一整段，觀眾最有感的地方，一句態度都沒有。**

數量和分布是兩件事。主角那邊早就有 `HERO_GONE_MOST`（最多連續幾句不
出現），吐槽這邊只有總數 —— 同一個形狀修過一次，另一個地方沒修。

加 `aside_gone_most`：不准連續超過 5 句沒有吐槽。加完第一次跑就叫了
（連續 8 句）。**而我第一版又忘了把這條寫進 prompt** —— 二十四那條的
同一個錯，隔了三小時再犯一次。

## 二十八、角色只是換了名牌的旁白

`parts` 那一步原本是「取代」：角色要講話就從旁白手上拿走一句。

量出來：11 句角色台詞跟被它取代的那句旁白，字面相似度**中位數 84%**，
八句只是把「它」換成「我」。角色沒帶進任何旁白說不出來的東西。

而取代原本是為了治「把插話拿掉，剩下的故事就不成立」—— 那個病後來由
`script.md` 治了（它被要求寫出一份「一句都不改也講得通」的旁白稿）。
**同一個病治兩次，第二道就只是在拆第一道的成果。**

改成追加，而且「旁白一個字都沒被動到」不做成門 —— `says` 那一列只會被
插入、不會被指派，**做不到比擋得住可靠**。

後續量到的三件，每一件都是「沒寫進 prompt 所以沒發生」：

```
第一人稱      8 句只有 2 句有「我」      —— prompt 根本沒寫這一條
一個人包辦    格陵蘭講了 6/8 句          —— 而它是受害的那一個，
                                           受害者複述自己被害不可能好笑
複述當反應    六句跟前一句相似度 23–42%  —— 而 `重申` 這一類就是在授權它
```

`重申` 換成 `誇張`（不准用旁白剛講過的數字，要用一句更大的話去頂），
另外兩件變成門。

## 二十九、一句二十個字，寫出來是五言絕句

使用者逐句指出九種破法，全部是同一個原因：

動詞抽象化        北歐人撐四百年就消失

壓縮出來的詞      它沒動，主人換了              沒搬家？沒反抗？沒同意？

## 三十、鏡頭有七成四的時間是靜止的，而目標是「運鏡絲滑」

使用者從第一天就說兩個目標：**故事性**和**運鏡絲滑**。我一直以為運鏡那
一半做完了 —— 因為「滑」的格子比「切」的多（38 比 12），報告上很好看。

量成片才發現問題不在那裡：

```
127 段　鏡頭在動 40 段、40 秒（26%）
        鏡頭靜止 87 段、114 秒（74%）
```

**它不是一直在切，是大部分時間根本沒動。** 一格拆成「停 → 移動 → 停穩」，
而移動只佔那一格的一半（`camera.travel` 0.5、上限 1.4 秒），所以一格
三秒就是移動 1.4 秒、停著 1.6 秒。

「滑 38 格」和「鏡頭在動 26%」都是真的，而**只有後者是觀眾感覺得到的**。
報告量的是前者。

掃出來的：

```
travel  上限    鏡頭在動
0.50    1.4s    29%    ← 原本
0.75    2.2s    45%
0.92    3.5s    58%
```

## 三十一、一格停十一秒，而門只出聲不擋

`STARE = 8.0` 那道門的註解寫著「不擋 —— 長鏡頭是一種選擇，但要被看見」。

而它看不見：50 格裡五格超過 6 秒，最長 **11.8 秒**。十一秒盯著同一塊地
不動，觀眾會以為片子卡住，而那正是「視覺刺激」的反面。

五格**全部停在主角身上** —— 那幾句台詞沒提到別的地名，模型就不換畫面。
它不知道「沒有新地名也可以換」：推近看細節、拉遠看它在哪、換一個一起
入鏡的對象，`see` 換一組鏡頭就會動。

加 `STARE_MOST = 9.0`（會擋），`STARE` 降到 6.0（出聲），而且把
「沒有新地名也要動」寫進 prompt —— 不然又是罰它不知道的規矩。
改完重排：最長一格 11.8 → 7.7 秒。

## 三十二、「誰用主色」是看模型把誰排第一

`lead = one["see"][0]` —— 主色給 `see` 陣列的第一個。

而那個順序是模型隨手寫的，沒有任何意義。後果是**同一塊地在不同格會換
顏色**，而觀眾是靠顏色認人的。

改成主角固定用主色（`hero`），主角沒被塗到的那幾格才退回用排第一的。

## 三十三、「這一支 API 做不到」被我寫成了「這件事做不到」

特效目錄裡有六種掛著 `renders: false`，其中「描邊界」的理由寫著：

> 渲染器的 `highlights` 有 `draw`，但只對線狀的 geoId 有效，而我們的字典
> 只有面。要做的話得先有線狀資料。

那句話每一個字都是對的。錯的是**從它推論到「所以做不到」**，然後把結論
寫進目錄 —— 一旦寫進去，就沒有人會再去想第二條路，包括我自己。

第二條路是拿 `lines` 串：輪廓切成 48 段、每段晚一格（0.033 秒）開始，
看起來就是一條線沿著海岸描過去。跟原本設想的 API 完全無關。

量出來的代價跟我怕的差很多：**48 條線只讓那一格慢 1.7%**（53.2 → 54.1
秒／180 格）。我本來打算「先試效能再決定要不要做」，而如果沒去量，
「一次塞幾十筆會不會爆」就會變成第二個不去做的理由。

做完的三件事：

```
輪廓預先算好      atlas_build 多出 outlines.json（242 塊 × 48 點，185 KB）
                 —— 執行期不碰隔壁那個 40 MB 的 geojson
群體要擋          「北約」在字典裡是 30 個 geoId，`geos[0]` 會安靜地只描
                 比利時。分鏡表寫描北約、畫面上是比利時，兩邊都不報錯
換日線那段要丟     經度 179 → −179 的兩點會被畫成橫跨整個地球的一條線
```

而「群體要擋」那道門加完**故意種一個違規**（拿「歐洲共同體」去描）看它叫
不叫 —— 它叫了：「是 12 塊地，描邊界一次最多 3 塊」。

順手也證明了畫出來是對的：48 點的輪廓畫成圖，格陵蘭、丹麥（利姆水道那
個缺口在）、冰島、挪威、美國、日本本州都認得出來。**第一次畫的時候忘了
吃緯度**（經緯度直接等比例畫），高緯度那幾塊被拉寬 1.8 倍；第二次改用
Mercator 又把弧度當成度，六張全壓成一條線。投影連錯兩次 —— 這就是
`README` 那條「所有鏡頭討論都要畫圖」存在的理由，兩次都是看圖才發現的。

## 三十四、搬家的腳本把 21 個中文檔名的檔案改成垃圾路徑

從 `Video_pipeline` 抽出來自己一個 repo 的時候，`git subtree split` 會把
`geo/` 這一層剝掉，所以要用 `filter-branch` 加回去：

```sh
git ls-files -s | perl -pe "s{\t}{\tgeo/}"
```

`git ls-files -s` 的輸出是 `<mode> <object> <stage>\t<path>`，而**非 ASCII
的路徑 git 會加引號**：

```
100644 abc… 0	"geo/refs/\345\217\203\350\200\203..."
```

所以 `geo/` 被插在引號**外面**，路徑變成 `geo/"\345\217\203…"` 這個字面。
21 個檔案（三份參考片規格、十八份稿子的對照組）名字全壞了。

**而且每一道門都過**：`geo.check` 過、`geo.checks._effects` 過、
`_parts` 過、`npm run validate` 過、`python3 -m geo.pipe.make` 列得出題目
—— 因為壞掉的那 21 個沒有一個是程式會讀的，它們是**人才會讀的東西**。

抓到是因為讀 README 的時候看到「`geo/refs/` 參考片拆解和規格（三份 md）」，
去 `ls` 發現沒有那個目錄。**要不是那一行寫著它應該存在，這 21 個檔案會
安靜地消失。**

修法兩件：

```
掃描要看的是路徑，不是程式跑不跑得動
  搬完之後 git ls-tree -r --name-only 兩邊 diff，一個字都不能差

git 讀路徑要關掉引號
  git -c core.quotePath=false ls-files -s
```

重做之後兩邊 89 個檔逐檔一致。

這是**「檔名說什麼內容就是什麼」那個形狀的第三次**（照片存成 `.jpg` 其實
是 WebP、音樂檔名取錯、這次）。前兩次修的是寫入那一端，而這一次的教訓
不一樣：**搬遷的驗收條件是「清單一樣」，不是「跑得動」**。

## 三十五、一個欄位名兩種意思，模型答完九分鐘才炸

「跑數字」的「數到幾」叫 `to`，而 `effects.check()` 把 `to` 一律當地名
（航線的「到哪」也叫 `to`），拿數字 3 去 atlas 查 —— `TypeError`。
**只要模型挑了這一種就一定炸**，而它在模型答完之後才驗：9 分鐘、$1.45。

改名 `many`。門：`_effects` 拿一份合法的「跑數字」和一份地名錯的「航線」
去驗，前者要過、後者要擋。

## 三十六、併掉「一樣的格子」，動作跟著消失

`_shape()` 只看相機和塗色，兩格一樣就併掉後一格 —— 而動作掛在格上。
開場「兩塊地拎起來比大小」那格跟前一格相機一樣，被當成重複，
**32 個動作剩 28 個，一個字都沒印**。帶著動作的格子不併；門：併格前後
動作數要一樣。

## 三十七、同一段程式抄三份，修一份還剩兩份

把動作欄位印成一行的那段，`board`、`look`、`watch` 各一份，都假設值
不是字串就是清單。「跑數字」帶進一個整數，三頁一起炸 —— 我修了過程頁，
分鏡頁照樣 500。收成 `board.fields()`。

## 三十八、`/spend` 安靜地印了兩天的 $0.00

頁面讀 `cost_usd`、`at`、`seconds`，`ask.send()` 寫的是 `usd`、`when`、
`took`。三個都不存在，`or 0` 接住了 —— 跟「還沒花錢」長得一模一樣。
修好是 32 趟 $19.48。**`or 0` 是這個形狀最常見的藏身處。**

## 三十九、數字跑不完就消失，觀眾看到「2 份條約」

`count_up` 的設定自相矛盾：最短顯示 0.9 秒，數字要跑 1.2 秒。1.0 秒的
格子裡數字停在 2；最長的 1.5 秒也只停 0.3 秒。而標籤釘在地圖上，一溢到
下一格就被滑走的鏡頭帶出畫面（只剩一個「約」）。

改成**先保證停住（hold），跑數字的時間去遷就它**，而且畫成字卡固定在
畫面上 —— 隔壁的標籤只吃經緯度，字卡吃畫面位置，也會跑數字。門：拿一格
放不下的餵給 builder，最後的數字停不滿 hold 就擋。

為了這件事加過一道「標籤有沒有出畫面」的檢查，改成字卡之後它擋的事不
可能發生了，當天就拿掉。

## 四十、字幕切在詞中間、以標點開頭

115 塊裡 9 塊：「己，挪威不服，」「脅，八個盟國」「、沒什麼人住的，」
「它。美國簽過三份條約，」。切塊一個漢字一塊，塞滿 12 個字才斷，
標點和詞尾就被擠到下一塊。

斷詞不用裝套件：**合成器的逐字事件本來就照詞斷好了**（「自己」「威脅」
各一筆）。切塊改成以詞為單位，沒標點可斷時往前退到下一塊開頭站得住。
中文數字加「年」另外黏（「九八六｜年」是合成器斷成兩個詞，照詞切還是會
切開 —— 修完逐塊看才發現的）。門在 `scene`：以標點開頭、切開詞、切開日期、
開頭掛著上一句的尾巴，都擋。

## 四十一、顏色看「這一格誰排第一」（三十二條的第二次）

三十二條修成「主角固定用主色」，而主角沒被塗的那幾格，主色還是給排第一
的 —— 美國一下紅一下藍，歐洲共同體先紅後藍，18 塊地在不同格換過顏色。
改成**整支片算一次，照「那塊地是誰」**：主角、cast 一人一色、其他中性；
群組裡屬於角色的那一塊照樣穿角色的顏色。門：同一個 geoId 兩種顏色就擋。

## 四十二、`[]` 被 `or` 當成沒寫

`tint = one.get("tint") or see` —— 模型寫 `"tint": []`（這一格刻意不塗）
會被當成沒寫，退回去塗 `see`。prompt 要教它「描述地圖原貌的那一格寫空的」
之前，要先讓程式做得到：`is None` 才算沒寫。**答應得到的事要做得到**，
而這一次是程式答應不到。
