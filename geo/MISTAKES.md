# 建這條路的時候抓到的錯

全部是 2026-09-26 一個晚上抓到的。**每一個都跑得完、exit code 0、
每一道當時存在的門都過** —— 它們只在有人打開畫面或量一次的時候才存在。

---

## 一、相機算得完全正確，鏡頭完全沒用

一個點單獨當鏡頭的時候，我給的外框是「剛好裝得下那個點」（±0.4°／±0.25°），
算出來 zoom 9.6。

```
紐約那一格      變成街道圖，看不出是紐約
圖勒基地那一格   一整片白色的冰，連海岸線都沒有
```

`covers()` 說裝得下 —— 它問的是「在不在畫面裡」，而那個問題的答案是對的。

**點是用來「指」的，不是用來「看」的。** 改成 ±7°／±3.5°（`AROUND`），
算出來 zoom 4.7：紐約看得到整個東岸，圖勒看得到格陵蘭西北角和海。

## 二、外框取全部領土，鏡頭就對著大西洋中間

```
挪威     −9.1 → 33.6    含央棉島
法國     −62 → 56       含法屬圭亞那、留尼旺
歐洲共同體 緯度 −21 → 60   含加那利、亞速
```

拿那個外框算相機，該亮的那塊地變成一個點。改成取**主體**：Natural Earth
每一筆都有 `LABEL_X/Y`（人挑過的、該放國名的地方），取包含那個點的那一塊。

然後丹麥只剩日德蘭半島，**哥本哈根在 12.6 被切在畫面外**。所以主體要能長：
把 `NEAR` 度以內的島併進來。

而 `NEAR = 4.0` 的時候挪威變成 58–80，因為**熊島（北緯 74.4）當了跳板** ——
它離本土 3.2 度所以併進來，併完北界推到 74.5，斯瓦巴就只差 1.6 度了。
一塊一塊接力，這是逐輪長大必然的行為。

掃 4.0 / 3.0 / 2.5 三個值，3.0 修好挪威而其他不動，2.5 跟 3.0 完全一樣 ——
**3.0 在穩定帶中間，不是踩在懸崖邊上。**

## 三、「91 個切點、平均 1.28 秒一格」，而畫面二十秒沒動

模型回了 91 個切點，其中一長串的相機、塗色、標記完全相同。畫面上那是一格，
不是十格。而報告說「平均 1.28 秒一格」，聽起來節奏很快。

**數字要說真話。** 併掉相同的（`_same()`），再另外印一個「不同的畫面幾種」。
第一版十二張取樣裡有八張一模一樣，而當時沒有任何數字說得出這件事。

現在有 `FEWEST` 那道門：整支片少於 8 種畫面就 raise。參考頻道 72 秒用了 14 種。

---

## 四、字幕把日期腰斬

「2026 年 9 月 22 日」被 12 字上限切成「2026 年 9 月 2」和「2 日」。

中文一個字一個字切看起來沒問題，**正是因為中文本來就一個字一個意思**；
數字和外文字不是。改成先切成「原子」（數字含單位是一個原子），再照原子排。

然後出現孤兒：「1991 年才被報紙挖出」＋「來。」，兩個字閃一下。修法是
先算塊數再照平均長度排，再加一道「太短就併進鄰居、併不下就借字」。

那一道自己也錯過兩次：**借完字之後前一塊變短了，而掃描已經走過開頭那個
孤兒**（第一版只在「併」之後重掃）；改成重掃之後又寫了 `at == 0: return`，
把後面的孤兒一起放掉。現在是「救不了的記下來，繼續救別的」。

## 五、量響度的門，量錯地方

`ffmpeg -v error … ebur128` 永遠回 `None`，於是門一直叫「loudnorm 可能沒
生效」—— 而它生效得好好的，**−14.6 LUFS 正中目標**。

`-v error` 會把摘要一起吃掉：ebur128 的「Integrated loudness」印在 info 等級。

**判錯的檢查比沒有檢查糟 —— 它會叫人去修沒有壞的東西。**

## 六、防「沒填的格子」的門，被維基的原文誤觸

`prompt_of()` 掃填完的全文找 `{xxx}`，而塞進去的維基原文裡本來就有
`{parabr}` 這種字。門當場叫「facts.md 還有沒填的格子：parabr」。

**要掃樣板，不是掃填完的結果。** 同一個形狀：這道門自己犯了它要擋的錯。

## 七、Azure 連不上，而錯誤訊息說的是網路

```
Connection failed (no connection to the remote host)
wss://germanywestcentral"/
```

設定檔那一行是 `region = "germanywestcentral"   # 金鑰綁區域…`，而我照
`split("=")` 取等號後面的**全部**，把註解一起送出去了。

錯誤訊息長得像網路問題。**送出去的東西要抓引號裡那一段。**

## 八、音色回成功、書籤全回來、每一格都對，而兩個角色是同一個人

第一版四個角色只指定音色。量完基頻：

```
旁白  198 Hz      ← zh-TW-HsiaoChenNeural
丹麥  202 Hz      ← zh-TW-HsiaoYuNeural
```

兩個都是 zh-TW 女聲，同一個音域，在耳朵裡是同一個人。而 Azure 回成功、
36 個書籤全回來、報告每一格都對。

現在 `spread_ok()` 每次合成完逐段量一次，兩兩差不到 1.15 倍就 raise。
**能算出來的就不要靠耳朵記得去聽。**

## 九、上游重寫了，下游的檔案還在

改了台詞重跑配音，而 storyboard、scene、成片全都還在 —— 每個檔案都存在、
每道門都過、`make` 看到「跑過了」就跳過，於是成片裡是**舊的畫面配新的聲音**。

更隱蔽的是模型那份 `*.raw.json`：storyboard 的答案是照句子編號寫的
（「第 12 句切到格陵蘭」），台詞一改，那些編號指的就是別的句子，
而程式照樣算得出秒數、照樣壓得出片。

兩個都用時間比：`paths.stale()` 和 `paths.raw_stale()`。時間比較笨
（碰一下檔案就算改過），但**誤判的代價是多跑一次，漏判的代價是一支錯的片**。

## 擋不住的

**一、地名靠掃字串認。** 稿子寫「聯合國大會場邊」掃不到紐約。故事檔的
`places` 可以補，補的會標 `+` ——但沒補、而且沒人發現的那一次，畫面只是
停在上一格。

**二、`quote` 對得上原文，不代表事實是對的。** 那道門問的是「這句話有沒有
出處」，不是「這個出處說得對不對」。維基寫錯的話，整條路都會照著錯。

**三、`entity` 少寫一個地方，那個地方就不可能出現在畫面上**，而畫面照樣
完整 —— 它只是少了一格。這是「靜靜回報零」在這條路上的樣子。

**四、我沒有真的看完那支片。** 我抽了十二格看，而它有 3502 格。
`verifyCuts.ts`（隔壁寫的）可以逐格比對，還沒接上。

## 十、門擋下來了，而半成品已經躺在那裡

配音那一步中間有兩道門（書籤數、音色分得開），而**合成在門之前**。
音色那道門擋下來的時候，新的 `said.wav` 已經寫進 `4-voice/` 了，
而 `said.json` 還是上一版的。

下一次跑：

```
done()   看到目錄裡有東西 → 「跑過了」
stale()  看到 wav 比 script 新 → 「沒過期」
make     跳過這一步
```

於是**成片用的是上一版台詞的聲音，而每一個檔案都在、每一道門都過**。
我是看到 storyboard 印出「133.1 秒、49 句」才發現的 —— 那是三個步驟之前
的數字，而新的台詞是 42 句。

修法跟 `paths.save()` 一樣：**寫進 `4-voice.part/`，全部做完、每道門都過，
才整個 rename 上去**。半路失敗就什麼都沒有，而「什麼都沒有」是 `done()`
判得出來的。

「破壞已經發生，產出還沒發生」，這個專案記過的第五次。

## 十一、一格裝不下，整趟三分鐘白費

模型挑了「美國＋挪威」，橫跨 156 度，算出來要 zoom 1.89 而畫面的地板是
1.91 —— **差 0.02**。`camera.fit()` 直接 raise，於是前面三分鐘的模型呼叫
和一分鐘的配音全部作廢。

而那一格是**救得回來的**：少留一點白邊就裝得下。

改成讓步三次（照設定 → 邊留少一點 → 連字幕那塊空間都拿來裝），每一次讓步
都出聲。真的裝不下才停，而且訊息說得出是第幾句、哪幾個地方、該怎麼拆。

**門要擋的是「不對」，不是「不方便」。**
